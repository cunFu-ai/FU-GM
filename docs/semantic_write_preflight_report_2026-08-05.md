# FU-GM 语义写入前审计与模型复测报告

日期：2026-08-05

## 本轮修复

这轮修复处理的是同一个根因：核心 GM 原先可以先调用带自由文本的写工具，再由公开回复审计器检查最终文字。NPC 工具会在公开回复产生前更新记忆、承诺和场景状态，因此“谁提到了庄园？”一类错误前提可能先被写成历史，锁定工具回复随后又绕过事后审计。

现在执行顺序改为：

1. 核心 GM 根据当前消息、最近公开聊天和权威状态提出工具调用。
2. NPC 回应/行动、NPC 建档或修订、场景回应、开场、转场，以及特质援用先进入语义写入审计。
3. 审计失败时，处理函数不会执行，消息事务不会启动，NPC 记忆与场景事实不会改变；错误原因作为可重试反馈返回同一个 GM 决策循环。
4. 审计通过后，原有 schema、规则与事务校验继续执行。
5. 工具成功回执仍是公开结果和状态变化的唯一权威来源。

数值型工具、纯查询、掷骰和已经由严格规则定义的结算不增加这一层模型调用。

## 特质援用

- 普通成功直接结算，不建立面向玩家的援用提醒。
- 失败后公开骰面，但不询问玩家是否重掷；系统静默等待 15 秒。
- 玩家主动援用身份、主题或故乡时，必须亲自说明它为何有助于本次检定。
- `invocation_rationale` 必须是玩家当前消息中的逐字连续片段，核心 GM 不得概括、润色或补写。
- 规则层检查原文溯源；语义层检查该理由与特质、当前检定是否真正相关。
- 到期失败叙述只有在平台确认送达后才提交原检定；等待期间出现合法援用时，旧失败叙述失效。

## FU-PL 修正

卡里巴村长测及短模型探针不再读取隐藏特质窗口后发送“我接受结果”。低风险失败会等待真实的 15 秒到期事务；重要失败只有在公开骰面已经显示失败时，模拟玩家才可能主动援用，并给出符合角色身份、主题或故乡的理由。

长测新增了错误前提探针：“刚才是谁提到了庄园？”此前公开对话没有庄园。正确行为是澄清无人提到，而不是为它虚构说话者或继续沿用该前提。

## 确定性验证

- 写入前审计、工具事务与检定规则定向回归：全部通过。
- 项目最终完整回归：`1991 passed in 19.19s`。
- 回归明确验证：首次错误 NPC 提案不会调用处理函数；模型修正后，处理函数只执行一次。

## 三模型语义探针

三个模型并发执行相同五项审计：

1. 拒绝把玩家问题中的“庄园”前提写成 NPC 既往言行。
2. 拒绝核心 GM 替玩家补写特质援用理由。
3. 拒绝玩家亲口说出、但与检定无关的理由。
4. 接受玩家亲口给出的相关理由。
5. 接受 NPC 对错误前提作出的权威澄清。

## 判断

Luna 的能力足以承担当前核心 GM 和语义审计任务。本轮证明此前的“庄园污染”和替玩家补理由主要是架构允许未审提案先落盘，而不是模型不能理解这些边界。模型仍可能首次提出错误工具参数，但现在错误只存在于一次未执行的内部提案中，不能再积累为战役事实。

DeepSeek 在狭窄审计任务上表现很好，但完整长测的 P95 与空响应仍不适合实时 QQ 核心 GM。Terra 仍是完整首场完成度较高的对照模型；是否替换生产核心，应由下一次完整、非并发长测决定，而不是只看这五个审计案例。
