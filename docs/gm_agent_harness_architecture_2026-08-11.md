# FU-GM Agent Harness 架构

本文记录 2026-08-11 完成的核心 GM 基础设施改造。目标不是模仿某个通用
编码 Agent 的界面，而是把其中适用于长线跑团的工程原则落实为可审计契约。

## 权威边界

- LLM 负责理解消息、选择能力、扮演 NPC、判断是否回应和组织自然语言。
- Python 负责规则、权限、事务、待决窗口、回合权、状态写入和投递顺序。
- 模型输出本身不是世界事实。只有成功的 `GMToolReceipt` 才能改变权威状态。
- 上下文压缩、长期记忆和场次摘要都是模型视图或派生索引；冲突时始终以
  当前存档、规则状态和原始消息为准。

## 单轮生命周期

`GMAgentLoopState` 为每次消息维护统一阶段、耗时、迭代次数和终止原因：

1. `observing_state`：读取本轮开始时的权威快照。
2. `building_context`：装配稳定工具契约、当前状态和最近公开聊天。
3. `requesting_model`：请求核心 GM 进行语义决策。
4. `dispatching_decision`：校验并执行工具，获得权威回执。
5. 必要时重新观察状态并继续循环。
6. `finalizing_transaction`：整条玩家消息统一提交或回滚。
7. `finished`：记录 `completed`、`silent`、`ask_user`、`deadline`、
   `provider_failure`、`exception` 等机器可读终止原因。

循环状态不复制 HP、命刻或场景等游戏数据，只负责协调和诊断，避免形成第二
份权威状态。

## 五层上下文治理

上下文治理只改变发给模型的副本，不修改存档和完整审计日志：

1. 工具结果预算：保留待决窗口、检定、资源变化和后续工具等恢复字段，裁剪
   大型展示字段。
2. 最近消息尾窗：通常保留最近 8 条，同时保护当前引用消息和当前轮事件。
3. 工具历史微压缩：去掉过期的重复错误，只给最近回执保留完整内容。
4. 结构化主动压缩：达到软阈值时按 JSON 结构折叠旧状态，而非截断字符串。
5. 硬阈值恢复：供应商仍拒绝时再次生成最小模型视图；当前消息、当前回合、
   待决窗口、活动命刻、现场 NPC 与公开事实不可裁掉。

每次调用都会产生不含玩家正文的 `context_manifest`，记录策略、字符量、近似
token、状态版本、提示布局版本和指纹。仪表盘可以据此发现上下文膨胀或缓存
布局意外漂移。

## 工具能力与执行元数据

所有工具 schema 按名称稳定排序，并声明：

- `side_effect`：只读或写入。
- `concurrency_safe`：只允许冻结快照上的纯读取工具开启。
- `destructive`：删除存档等不可自然撤销操作。
- `max_model_result_chars`：模型视图的结果预算，不影响完整回执。
- `defer_group`：已经由领域组件异步执行的侧链类别，例如 NPC 蓝图与地图渲染。

普通写工具默认串行。当前不会仅因元数据存在就并行执行工具；后续若增加并行
调度，也只能并行纯读取，且必须在同一版本快照上运行。

核心 GM 不会每轮看到完整工具库。常用冒险能力可以直接开放；陌生的存档、
地图、地下城等跨域任务才通过 `discover_capabilities` 加载对应窄工具集。待决
窗口的后续能力只能由权威回执授权，不能通过能力发现绕过。

## 群聊顺序与投递

AstrBot 的 `ChannelTurnGate` 以频道为单位串行处理自然消息。闸门覆盖：

`后端请求 -> 权威事务提交 -> QQ发送 -> 上游送达确认`

因此下一条消息不会在上一条回复尚未真正出现在群里时读取一条更靠后的时间
线。不同频道仍可并行。新的直接艾特、回复时悠或私聊可以丢弃尚未提交的普通
群聊缓冲；已经进入后端事务的旧请求则由活动版本和新鲜度守卫安全终止，不能
暴力杀线程。

## 长期记忆生命周期

`TopicMemoryStore` 的 Markdown frontmatter 记录：

- `snapshot_version_at_write`：生成这条派生记忆时的权威状态版本。
- `verified_at`：人工或受控流程真正核验后才写入。
- `superseded_by`：旧记录保留供审计，但默认不再召回。

每 5 场或 24 小时进行一次保守整理。正文、可见性、类型、标题和实体均相同的
重复记录可自动合并；同一主题但正文不一致时只生成
`conflict_candidates`，等待语义模型或人工核验，绝不由本地词法规则决定哪个
剧情是真的。

## NPC 与其他侧链

重要 NPC 的战斗蓝图、NPC 声线、地图生成和场次总结可以在独立侧链中运行。
侧链只向核心循环返回结构化结论、证据或经过 Python 编译的规则卡，完整提示与
原始输出留在后台日志。普通路人继续使用轻量档案和模板，不为每个 NPC 启动一
个长期 Agent。

## 后续拆分边界

本轮没有为了减少文件行数而重写确定性规则。`ActionInterceptor` 仍较大，后续
应按检定、攻击、法术、NPC能力等规则域渐进迁移，并在每个域保持相同的事务和
回执契约。它不应与核心 Agent 循环、语义路由或表达模型重新耦合。

部署副本（本机通常为 `~/.fu-gm`）与本源码树相互独立。源码验证通过不代表线上
副本已经更新；部署时仍需显式同步、重启并检查 `/health` 与真实消息路径。
