# FU-GM LLM 语义状态边界审计

日期：2026-07-18

## 目的

本审计先于新的长测执行。目标不是把关键词判断机械地替换成 LLM，而是确保 Luna 参与语义识别后不会把提议、尝试、请求或表达文本误写成既成事实。

## 必须遵守的状态边界

1. **LLM 只提出候选，不直接拥有持久化写权限。** 每个可写候选都必须附带稳定对象 ID 与逐字证据，程序只做成员、ID、证据来源和事务一致性校验。
2. **当前发言与历史上下文分权。** 当前消息可证明玩家这一次实际做了什么；历史只用于消解指代或匹配已存在对象，不能替当前玩家补出新行动。
3. **提案、请求、递出、尝试和完成是不同状态。** `proposed/requested/offered/attempted` 均不得升级为 `completed`，除非规则裁定或有权决定的对象明确回应。
4. **玩家可见文本与后台状态原子提交。** 公开事实必须是已经发送文本中的连续原文；表达模型未说出的结果不得只在后台成立。
5. **模型不可用、结构无效、证据不一致时零写入。** 不得退回关键词推断后继续行动、创建命刻、移动场景或修改第零章档案。
6. **一个事实只有一个提交者。** 安全声明、Session 0 更新、NPC 承诺、场景移动等各自只能由一个生命周期组件提交，避免同一句话被多个模块重复或以不同解释写入。
7. **高影响状态需要独立确认。** 跨消息确认、NPC 条件完成、整项待决问题关闭、角色归属迁移等操作需要第二次语义复核或稳定的结构化规则结果。

## 已发现的风险

### 严重

- `LLMMessageArbiter` 的动作事实或复合行动复核失败后，在允许 fallback 时仍会把原句送入后续 Action Brain。提示词虽然写着“结果待定”，但不能保证下游不会提交错误事实。
- `LLMActionBrain._postprocess_action` 会在 Luna 输出之后再次用关键词覆盖动作、目标、难度和命刻。观察到“车辙、追兵、潮水”等词甚至可以创建预制威胁命刻。
- `LLMSessionZeroFacilitator` 默认开启本地快速路径，并在 Luna 输出后调用 `_merge_deterministic_updates`，关键词提取可以覆盖正确的模型判断并直接修改世界与角色草稿。
- 开团前共识 `PreSessionConsensusFacilitator` 仍是完整的关键词写入器；即使语义路由选择静默，观察分支也可能把玩家闲聊写成共识。
- `SceneOrchestrator.discuss_session_zero` 在 Session 0 LLM 处理前调用 `SafetyManager.parse_and_declare`，自然语言误判会先落库，后续模型无法撤回。

### 高

- `SceneTransitionCoordinator` 接受表达文本中的“抵达/进入”作为兼容证明，表达模型的一句修辞可能改变持久化地点。
- `SceneAccessBoundary` 在语义路由后仍独立解析原文中的移动关键词，可能拦截一个未发生的计划或把模糊的“门”匹配到错误条件。
- `SceneWorldResponsePlanner` 的 `public_fact` 不要求逐字出现在 `reply` 中，模型可让后台知道一条玩家从未听见的事实。
- 主动 GM 节拍结束后，`settle_conditions_from_public_outcome` 用正则判断承诺是否兑现，可能把相似措辞误判为开放条件已经完成。
- `SceneConditionMatcher` 的 `complete` 以及 NPC 待答问题全部完成目前主要依赖一次模型判断；虽然有逐字证据约束，高影响关闭操作仍可能误配。

### 中

- 移动范围复核失败目前被视为“建议性失败”，会保留第一遍分类；跨场景移动属于高影响状态，不应继续。
- Scene 0 的确认、清除 pending proposal 与正式写入不是统一事务，存在清除了提案却只写入一部分字段的风险。
- 多个 recovery pipeline 继续以关键词重写 Luna 的动作。部分属于合法的规则标准化，部分却在重新解释玩家意图，需要按“结构校验”和“语义改写”拆开。
- 默认 `allow_heuristic_fallback=True`，而当前 `.env` 未关闭，生产运行实际允许旧关键词逻辑在模型失败时接管。

## 分批修复顺序

1. 关闭生产关键词 fallback；所有必要语义子复核失败统一返回 `semantic_route_unavailable`。
2. 让语义路由的动作证据成为 Action Brain 唯一意图来源；禁止 LLM 后处理器用关键词重建目标、难度或命刻。
3. 移动、公开事实与 NPC 条件只接受结构化、逐字证据支持的提交。
4. 为 Session 0、开团前共识和安全边界建立统一的候选更新审查器，禁用写状态快速路径和确定性合并。
5. 为高影响关闭操作加入独立确认，并让提案确认、正式写入、清除提案原子化。
6. 完成对抗性单元测试后才恢复 20 场长测；长测期间不再边跑边补。

## 长测恢复门槛

- “示意对方接过物品”不会变成“对方已经收下”。
- “讨论要不要去某地”不会移动场景。
- 表达文本自行出现“已经抵达”而无结构化结果时不会切换地点。
- Luna 超时、空响应、无效 JSON 时不写世界、角色、安全、命刻、条件或位置。
- 未确认提案不会写入；确认只应用被引用的那一项提案。
- 普通观察不会创建、推进或倒转威胁命刻。
- GM 主动叙述只有在逐字公开兑现条件时才关闭对应条件。
- 相关定向测试与完整单元测试全部通过。
