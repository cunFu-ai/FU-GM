# 卡里巴村首场三模型并发长测报告

日期：2026-08-06

## 测试结论

本轮确实同时测试了三个模型，不是只运行 Luna。`scripts/run_kariba_model_matrix.py` 为三个模型分别建立隔离的战役目录和进程，并发运行同一套卡里巴村越狱流程：

- `gpt-5.6-luna`：使用独立 Luna API Key。
- `gpt-5.6-terra`：使用 ai-pixel 默认 API Key。
- `deepseek-v4-flash`：使用 DeepSeek 官方端点和独立 API Key。

并发测试适合比较端到端完成度与规则行为；延迟会受到共享网络、主机负载和供应商并发限制影响，因此不等同于单请求基准。

## DeepSeek 卡死的真实原因

本轮不能把 DeepSeek 的 8/19 简单归因为模型能力不足。诺艾尔明确攻击和防御时，DeepSeek 正确申请了 `conflict` 能力，但动态能力目录只把 `perform_character_action` 放在 `rules` 领域，没有放进 `conflict` 领域。模型因此看不到提交玩家攻击或防御的正确工具，只能错误尝试 `resolve_rule_window`，连续失败后触发熔断。

证据包括：

- 权威状态明确显示当前行动者是诺艾尔，且不存在待决窗口。
- 三次 `discover_capabilities(domain=conflict)` 均未返回 `perform_character_action`。
- 模型收到的工具集中只有开始/结束冲突、NPC回合和窗口处理能力。
- 上一轮并发矩阵中，DeepSeek 曾跑到 69 轮并获得 17/19，说明它并非必然无法完成这套流程。

现已把 `perform_character_action` 加入冲突领域，并新增回归测试。玩家在冲突中攻击、防御、施法或使用技能时，只申请 `conflict` 领域也能获得正确提交工具。

## 评估器误报

Luna 与 Terra 唯一共同失败项是 `equipment_outcome_resolved`。两条分支里，角色已经明确放弃被守卫收缴的装备并撤离或承担败北后果，故事状态是合理的；但长测导演没有把“撤离时有意识留下装备”写进测试记账，因此报告误判为装备未解决。

现已修正测试导演：角色明确沿出口逃走时，仍不可用的被收缴装备会记为有意识留下。该改动只修正评估，不篡改实际角色状态或原始测试结果。

## 建议

当前核心 GM 首选仍是 Terra：本轮完成度最高、工具调用零失败、静默与应答最稳定。Luna 适合作为第二候选，但需要继续观察尾延迟和工具循环耗尽。DeepSeek 不应因本轮框架漏权而被淘汰；修复后值得再做冲突专项对照，它的速度和缓存效率很有价值。

生产群聊仍只应由一个权威模型提交状态。三模型并发仅用于隔离存档的评测，不能让三个模型同时回复真实玩家。
