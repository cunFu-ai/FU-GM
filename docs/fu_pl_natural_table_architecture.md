# FU-PL 自然桌运行方式

FU-PL 只用于自动化测试，不进入 AstrBot 的真实玩家消息链。它的目标不是代替规则引擎，而是用多个彼此独立的玩家视角检验 FU-GM 在真实群聊节奏下是否仍能主持。

## 两种测试模式

- `natural`：默认真人感测试。每条公开消息同时发送给所有 FU-PL；每个玩家模型独立决定 `speak` 或 `wait`，框架不指定下一位发言者。
- `coverage`：规则覆盖测试。继续按固定说话人与输入覆盖技能、装备、命刻和场景生命周期，结果稳定但不用于评价真人感。
- `legacy`：仅保留旧回归兼容，不作为新的质量基准。

运行示例：

```bash
.venv/bin/python scripts/run_20_session_campaign_test.py \
  --sessions 1 \
  --player-mode natural \
  --setup-only
```

## 一条公开消息如何流转

1. GM 或玩家消息成为 `PublicTableEvent`。
2. 同一事件广播给每个持久化 `PlayerMind`。
3. 每个 FU-PL 只读取公开聊天、自己的角色资料、自己的私有创作意向和行动条。
4. 模型返回是否发言、受众、消息类型、文本与自主延迟。
5. 传输层按模型自己给出的理解与打字延迟发送最先到达的一条；其他候选保留为过期草稿，看到新消息后必须重新判断，不能机械补发。
6. 全桌都等待且没有待决窗口时，才允许 GM 心跳推动一个真实会自行发展的 NPC、环境或威胁。

框架的排序只模拟群聊消息到达顺序，不替玩家产生发言意图。延迟完全相同时使用由事件编号和玩家名生成的稳定传输抖动，不按人格注册顺序偏袒固定玩家。候选草稿不会写入“自己已经说过的话”或公开承诺；只有真正送达群聊后才提交玩家发言历史和承诺。

## 第零章

固定测试台词不会在 `natural` 模式中发送。每个玩家只收到简短的个人偏好、可选世界种子和分阶段角色工作表，而不是未来完整台词；这些内容不是世界事实，也不代表全桌共识。FU-PL 应当根据当前讨论逐步提出、修改或放弃想法。

第零章行动条只向本人显示自己的世界贡献缺项和角色草稿缺项。完成条件来自 `SessionZeroManager` 的权威清单；脚本走到某个编号不会自动判定完成。清单齐备后，由 GM 询问是否进入第一章，任何玩家都可以自然回应，框架不会伪造固定玩家代表全桌同意。

## 冲突场景

所有 FU-PL 都会收到公开行动条，包括当前行动者、行动轮和公开待决窗口：

- 当前行动者可以声明规则行动。
- 其他玩家仍可讨论战术或等待，但不能结算抢跑动作。
- 待决窗口只向所属玩家开放，其他人只能知道有人正在处理选择。
- 自动命刻属于规则状态，不由 FU-PL 假装推进。

## 权限边界

FU-PL 没有任何写入工具。它的输出只是一条普通玩家消息。FU-GM 仍通过语义代理选择工具，Python 负责参数校验、事务提交、骰子、资源、回合和事实落盘。玩家模型的私有想法永远不能直接变成世界事实。

## 成本与报告

自然模式每个公开事件会产生“玩家数”次模型判断，因此请求数高于固定说话人模式。所有 FU-PL 共用同一客户端、稳定系统提示和工具为空的固定请求形态，以提高提示缓存复用率。

长测报告中的 `natural_table` 会记录：

- 第零章与冒险阶段的广播周期数；
- 独立 `speak/wait` 决策数；
- 全桌等待与 GM 心跳次数；
- 过期草稿重判次数；
- 实际发言者分布。

这些指标用于发现“某位玩家被框架固定点名”“全桌长期沉默”“玩家模型总抢话”或“GM心跳没有带来可回应新变化”等问题。规则正确性仍由独立的覆盖模式和单元测试负责。
