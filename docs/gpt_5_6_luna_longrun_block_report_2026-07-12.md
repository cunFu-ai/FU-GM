# gpt-5.6-luna 20 场长测阻塞报告

日期：2026-07-12

## 结论

FU-GM 已统一配置为 `gpt-5.6-luna`，但该模型当前无法支撑真实 20 场长测。阻塞来自模型供应端持续返回 HTTP 502，不是 API Key 额度、FU-GM 状态机或本地网络故障。

本次没有用启发式动作或固定叙事模板冒充模型结果。严格语义模式在第一条无法完成的群聊路由处停止。

## 证据

- 主、备端点的模型目录均包含 `gpt-5.6-luna`。
- 简单 JSON 探针曾成功一次，耗时约 6.6 秒。
- 简化 GM 开场探针曾通过备用端点成功，耗时约 9.7 秒，但出现一次把 NPC“失忆旅人”误写成玩家本人的实体归属风险。样本不足，暂不据此修改框架。
- 受限玩家回应探针成功，耗时约 3.9 秒，未替 GM 宣布结果。
- 严格 20 场长测的第一条普通群聊路由在主、备端点间轮换 60 次，约 750.8 秒后仍失败并返回 HTTP 500。
- 此后每 30 秒执行一次 Luna 可用性探针，连续 21 次均返回 HTTP 502，没有形成连续三次可用窗口。
- 同一 API Key、同一主端点的对照请求中，`gpt-5.4-mini` 约 1.7 秒成功，而 `gpt-5.6-luna` 约 0.8 秒返回 HTTP 502。这排除了账户整体额度耗尽和 FU-GM 请求格式错误。

## 本轮完成的框架改进

- 主端点与 `cf` 备用端点自动故障转移。
- 为备用端点添加可配置 HTTP User-Agent，解决 Cloudflare 403/1010 请求指纹拦截。
- LLM 遥测记录实际请求端点。
- 严格语义长测禁用 Action Brain、Expressor、消息路由、场次总结和 FU-PL 的静默启发式回退。
- 非预期 HTTP 错误立即停止长测，避免后续状态建立在缺失回合之上。
- FU-PL 对非法输出最多进行两次语义修复，而不是立刻套用固定玩家模板。
- 报告区分上游可用性、模型能力、FU-GM 框架和测试执行器问题。
- NPC 已公开答复会写入场景状态，后续不再完整重复同一放行条件。
- 长测补足轮次改为根据上一条 GM 公开回复实时生成，避免跨场景沿用旧 NPC 和旧压力。
