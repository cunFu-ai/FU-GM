# FU-GM 后台委托系统

## 目标

后台委托用于一项确实需要多轮读取、规划和工具调用、但玩家无需停下聊天等待的工作，例如：

- 补全多项世界设定；
- 整理多份规则资料；
- 为尚未登场的重要 NPC 准备档案和战斗蓝图；
- 进行不触碰当前场景、回合或待决窗口的幕后准备。

普通问答、一次即可完成的修改、当前场景行动、战斗回合、命刻即时变化、角色选择和安全边界不进入后台。地图图片生成暂时也不进入通用后台执行器，仍由地图专用流程负责。

## 运行方式

1. 核心 GM 判断任务确实较长后，调用 `delegate_background_task`，提交完整目标、授权范围、完成标准和最小能力领域。
2. 前台立即确认受理并结束本轮，QQ群或私聊可以继续正常对话。
3. 后台模型在没有持有战役锁的情况下读取任务和权威状态，每轮只选择一个工具。
4. 该工具通过普通 `GMToolRegistry` 事务执行。Python 仍负责参数校验、权限、状态版本、提交和回执。
5. 一步结束后释放战役锁；下一轮重新读取最新状态，不沿用过期的世界快照。
6. 完成标准全部满足后，后台任务排入独立通知箱。AstrBot 将通知送回原群或原私聊，确认送达后才写入公开聊天记录。

这意味着后台任务不是一段长期持锁的 Agent 循环，也不是让模型直接修改 JSON。每一步仍有成功工具回执，前台消息可以在任意两个步骤之间正常提交。

## 状态与控制

任务状态包括：

- `queued`：等待下一步；
- `running`：当前正在规划或提交一步；
- `waiting_user`：缺少无法自行推断的必要信息；
- `completed`：完成标准已经满足；
- `failed`：连续失败、超过步骤上限或没有安全能力可用；
- `cancelled`：发起者要求停止。

玩家可以用自然语言查看任务列表或进度、取消本人任务，以及回答等待问题。非发起者不能替别人取消或回答。取消只阻止后续步骤，已经由成功工具回执提交的事实不会伪装成已回滚。

## 持久化与恢复

任务保存在数据目录的 `_service/background_delegations.json`。服务重启时，原本处于 `running` 的任务会恢复为 `queued` 并重新读取最新权威状态。待发送通知同样持久化；AstrBot 使用本地发送日志和服务端送达确认避免重复发送。

仪表盘的“后台委托”卡片显示目标、完成标准、步骤、等待问题、失败原因和通知状态，但不会向玩家公开模型轨迹、NPC 秘密或私密提示。

## 安全边界

通用后台执行器只开放授权领域内的读取工具和少数准备/资料类写工具。场景、冲突、命刻、角色行动与决策窗口始终留在前台。NPC 战斗蓝图可以后台生成和归档，但不会因此让 NPC 入场或加入冲突；真正登场时仍由核心 GM 在当前场景事务中提交。

同步地图渲染目前会在运行期间接触实时世界状态，因此被明确排除。等地图流程改成“冻结快照生成 + 版本校验 + 原子发布”后，才适合接入通用后台执行器。
